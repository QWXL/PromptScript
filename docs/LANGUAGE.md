# PromptScript 语言规范

> 本文档是 PromptScript 语言的规范（source of truth），随包发布。实现、CLI 与编辑器工具均以本规范为行为契约。

## 1. 基本概念与术语

- **帧（Frame）**：一份文档的顶层作用域。帧包含绑定表（bindings）和可选的父帧指针。
- **绑定（Binding）**：名字到值的映射，来源于 `@set`、宿主注入或 include 子帧。
- **文章模式 / 顶层模式**：文件顶层及被 include 文件顶层的解析模式，允许原文行和指令行混合。
- **代码模式**：`@if` / `@else` / `@for` 块内部的解析模式，每行必须是语句或字符串字面量。
- **槽位（Slot）**：插值表达式 `{…}`，用于在文本中嵌入动态值。
- **硬空缺 / 软空缺**：区分“从未解析”和“解析为 `undefined`/`null`”两种空缺状态。

---

## 2. 语法与表达式

### 2.1 行结构与两种模式

文件由行序列组成。解析器首先去除行首空白（`trimStart`），然后根据以下规则判定行类型：

| 行类型    | 判定规则                                                   | 示例                                                                     | 语义                                     |
| ------ | ------------------------------------------------------ | ---------------------------------------------------------------------- | -------------------------------------- |
| 指令行    | 以已知指令名开头（`@set`、`@if`、`@else`、`@include`、`@for`）       | `@set n = e`、`@if(e) {`、`@else {`、`@include("path")`、`@for v in rec {` | 驱动结构或绑定，不渲染本体                          |
| 文档行    | 不是指令行，且不以 `@` 开头                                       | `任意文本{expr}`                                                           | 文本渲染，插值槽位求值后替换                         |
| 闭合行    | 恰为 `}`，或 `} @else {` / `} @else @if(expr) {` 同行连接      | `}`、`} @else {`、`} @else @if(b) {`                                      | 闭合花括号块（同行连接时同时附着 `@else` 或开 else-if 链） |

#### 文章模式

- 适用位置：文件顶层及被 include 文件的顶层。
- 文档行可包含任意文本和插值；指令行按上述规则识别。
- 行首空白在文章模式下是内容的一部分，会被保留。

#### 代码模式

- 适用位置：`@if` / `@else` / `@for` 花括号块内部。
- 每行必须是：
  - 指令行（`@if`、`@else`、`@include`、`@for`）
  - 字面量（`""`或`''`），可包含插值，如 `"文本{expr}"` 或 `'文本{expr}'`。
- 缩进自由，仅用于排版，不进入渲染内容。
- 空行表示纯空白，不渲染；如需输出空行，必须写 `""` 字面量行。
- 字符串字面量内部的空白按字面处理。

> 注意：代码模式中所有输出文本必须写成字符串字面量行，不能像文章模式那样直接写原文行。

### 2.2 指令

#### `@set name = expr`

在当前文档帧声明变量或记录绑定。

- **位置无关**：同一帧内，正文可以引用声明位置之后的 `@set`。
- **提升**：所有 `@set` 在帧渲染开始时按源码顺序求值。
- **值类型**：字面量（string / number / bool / null）或记录（record）。
- **限制**：`@set` 仅允许出现在帧顶层（文章模式顶层），出现在块内是语法错误。

示例：

```promptscript
@set tone = user.relationship_level.value > 50 ? "亲切" : "客气"
@set vip_label = {"svip": "超级会员", "free": "免费会员"}
```

#### `@if(expr) { … }` / `@else { … }`

条件渲染块。

- **语法**：
  - **`@if(expr) {` 开启行**：单独占一行开启（作为 else-if 链的 `@if` 除外，见下）。
  - 花括号配对按纯计数规则检查：未闭合或多余的 `}`、孤立的 `@else`、同一 `@if` 块出现多个 `@else` 均为语法错误。
- **`@else`**：附着在紧邻的前一个完整 `@if` 块之后；可与闭合 `}` 同行连接（`} @else {`）。也可紧跟 `@if` 组成 **else-if 链**：`} @else @if(expr) {`（或独立行 `@else @if(expr) {`），等价于手写 `@else { @if(expr) { … } }` 的语法糖，可链式任意长度。
- **闭合**：`}` 独占一行闭合，或与紧随的 `@else` 同行连接（`} @else {` / `} @else @if(expr) {`）。
- **块内容**：采用代码模式（见 2.1）。
- **语义**：谓词 `expr` 为真值时渲染 if 分支，否则渲染 else 分支（若存在）；没有 else 则跳过。
- **嵌套**：支持嵌套 `@if`；不提供 `@elseif`，可用嵌套 `@if` 实现。
- **谓词**：没有回退概念；若谓词引用未绑定的名字，将产生运行期错误。

示例：

```promptscript
@if(user.relationship_level.value > 30) {
  "这是老朋友："
  "- 根据天气调整问候"
  ""
  "- 第二段"
}
@else {
  "这是新朋友："
  "- 先自我介绍"
}
```

#### `@include("path")`

在加载阶段将另一份 PromptScript 文件作为子帧内联到该位置。

- **路径**：带引号的字符串参数；既可以在顶层出现，也可以在块内出现。
- **展开**：被包含文件本身是完整文档，其顶层采用文章模式；整体进行 dedent（以最小公共缩进为准，空行不参与计算）后解析为子帧。
- **作用域**：展开后的内容拥有独立作用域（子帧），见 3.2。
- **错误**：文件缺失或循环引用将导致加载期错误。
- **读取缓存**：同一加载（resolve）过程中，同一路径只读取一次磁盘；多个 `@include` 引用同一文件（如顶层与循环体内各一处）共享缓存文本，但各自解析为独立子帧。

#### `@for 变量[， 变量] in 数据源 { … }` / `@else { … }`

循环渲染块。

- **形式**：
  - `@for v in 记录表达式 {`：`v` 绑定每条**值**（如 `@for v in vip_label {`）。
  - `@for k, v in 记录表达式 {`：`k` 绑定**键**、`v` 绑定**值**。
  - `@for i in 1..5 {`：整数范围，闭区间 `[1, 5]` 共 5 次，`i` 绑定计数器（非负整数，不支持负数/小数/步长）。
- **语法**：`@for` 行必须以 `{` 结尾、`}` 独占一行闭合，或与紧随的 `@else` 同行连接（与 `@if` 一致）；`@else` 附着规则与 `@if` 相同；`@else` 同样支持同行连接与 else-if 链（`} @else {` / `} @else @if(expr) {`）。块内采用代码模式；支持嵌套 `@for`；`@for` 可在顶层或 `@if` 块内出现。
- **空迭代**：空记录或 `start > end` 时渲染 `@else` 分支（若有），否则不渲染。
- **作用域**：循环体是隐式子帧；循环变量临时遮蔽外层同名绑定（宿主注入、`@set`、外层循环变量），循环外恢复。循环变量不进帧级声明表（无重名检查、无 TDZ）。
- **空缺**：数据源引用未绑定名 → 渲染期 `E_UNBOUND`（与 `@if` 谓词一致）；循环体内沿用现有空缺矩阵规则。
- **范围是 `@for` 局部语法**：`1..5` 不是通用表达式（`@set x = 1..5` 仍是语法错误），仅在 `@for` 指令内识别。
- **循环内 `@include`**：允许；被包含文件以当前迭代的子帧为父帧，可直接引用循环变量；被包含文件内的 `@set` 与循环变量同名时静默遮蔽循环变量。空迭代时循环体不执行。
- **迭代上限**：单次 `@for` 迭代超过 32768 次 → 渲染期 `E_FOR_LIMIT` 错误（防失控大循环；上限按单个 `@for` 计）。

示例：

```promptscript
@set vip_label = {"svip": "超级会员", "free": "免费会员"}

@for v in vip_label {
  "- {v}"
}
@for k, v in vip_label {
  "- {k}：{v}"
}
@for i in 1..3 {
  "第 {i} 段："
  "正文内容"
}
@for k, v in vip_label ?? {} {
  "- {k}：{v}"
}
@else {
  "暂无会员标签"
}
```

### 2.3 表达式语言

#### 字面量

| 类型   | 语法                                  | 说明                                                                     |
| ------ | ------------------------------------- | ------------------------------------------------------------------------ |
| 字符串 | `"…"` 或 `'…'`                        | 可包含 `{expr}` 行内插值；转义最小集：`\"`、`\\`、`\n`、`\t`、`\{`、`\}` |
| 数字   | 非负十进制整数或小数，如 `42`、`3.14` | 不支持负数（没有 `-` 运算符）                                            |
| 布尔   | `true` / `false`                      |                                                                          |
| 空值   | `null`                                |                                                                          |

字符串内的插值使用与槽位相同的读取器；字符串中字面 `{` 需转义为 `\{`，字面 `}` 无需转义（见 4.5）。

#### 路径引用

- 路径由标识符通过点 `.` 连接，如 `user.name`、`env.weather`、`user.relationship_level.value`。
- 支持无点裸标识符，如 `tone`。
- 标识符是“宽松标识符”（见 2.4 词法），支持中文。

#### 运算符

按优先级从高到低：

| 优先级 | 运算符            | 结合性 | 说明                                                     |
| ------ | ----------------- | ------ | -------------------------------------------------------- |
| 1      | `r[key]`、`r.key` | 左     | 记录属性访问；点访问要求键为合法标识符（数字键只能下标） |
| 2      | `!`               | 右     | 逻辑非                                                   |
| 3      | `==` `!=` `<` `>` | 左     | 比较                                                     |
| 4      | `&&`              | 左     | 逻辑与                                                   |
| 5      | `\|\|`            | 左     | 逻辑或（所有上下文一致）                                 |
| 6      | `??`              | 左     | 空值合并（右操作数为任意表达式）                         |
| 7      | `? :`             | 右     | 三元条件，可嵌套                                         |

说明：

- `??` 左结合，可链式：`a ?? b ?? c`；右操作数可以是任意表达式（如 `a ?? (b ?? c)`、`x ?? y == 1`）。
- 括号 `()` 用于改变优先级。
- 槽位、`@set`、`@if` 使用同一语法；`||` 一律是逻辑或，没有回退别名语义，回退请用 `??` 或 `|`（见 2.4）。

#### 记录

- 记录字面量：`{"k": v, 0: v, bareKey: v}`，其中键可以是引号字符串、裸标识符或裸数字；所有键统一转换为字符串。
- 值只能是字面量（string / number / bool / null），不支持嵌套记录或表达式值。
- 访问：`r[key]` 或 `r.key`（后者要求键为合法标识符；数字键只能通过下标访问，如 `r["0"]` 或 `r[0]`）。
- 直接渲染记录值会导致运行期错误；必须通过下标或点访问取出具体字段。

示例：

```promptscript
@set vip_label = {"svip": "超级会员", "free": "免费会员", 0: "零号"}
用户标签：{vip_label[user.vip] ?? "未知"}
数字键：{vip_label["0"]}
```

#### 暂不支持的特性

函数调用、算术运算（`+ - * /`）、include 参数、嵌套记录、数组、注释指令（C 风格注释见 2.5）、`@elseif`、`..` 范围语法（仅 `@for` 指令内可用）、`in` 关键字（仅 `@for` 指令内识别）。

### 2.4 插值（槽位）

槽位用于在文本中嵌入表达式，语法为 `{expr}`。

#### 回退形式（所有表达式上下文一致）

槽位、`@set`、`@if` 使用同一语法；以下回退形式在表达式最外层（剥掉整个表达式的外层括号后）生效：

| 形式               | 语义         | 说明                                                                  |
| ------------------ | ------------ | --------------------------------------------------------------------- |
| `path ?? fallback` | 空值合并回退 | 推荐形式；`fallback` 按任意表达式求值（通常使用带引号的字符串字面量） |
| `path \| 字面量`   | 纯字面量回退 | 管道后的文本按字面输出，不解析路径、不进行插值。                      |

- `|` 仅在表达式最外层生效（`@if(expr) {` 的括号、`@set x = (… | 回退)` 的外层括号会先剥掉）；出现在更深嵌套（括号、下标内）是语法错误。
- `|` 右侧为直到表达式结束的原始文本；可使用 `\}` 转义输出字面 `}`，`\\` 输出字面 `\`。例如 `{name | 未知}` 输出 `未知`；`{name | a\}b}` 输出 `a}b`。
- `??` 右操作数若为路径且未绑定，将触发硬空缺错误。建议使用带引号的字符串字面量提供默认值，例如 `{env.weather ?? "未知"}`。
- `||` 一律是逻辑或，没有回退别名语义；回退请用 `??` 或 `|`。

#### 槽位读取规则

- 读取器从 `{` 开始，以括号深度计数；初始深度为 1。
- 遇到字符串字面量（`"` 或 `'`）时，跳过其中内容，字符串内的 `}` 不参与深度计数。
- 遇到记录字面量 `{` 时深度加 1，遇到 `}` 时深度减 1；深度归零的 `}` 闭合槽位。
- 槽位内需要输出字面 `}` 时使用 `\}` 转义（引号内除外）。字符串字面量内需要输出字面 `{` 时使用 `\{`。
- 记录字面量是唯一包含花括号的表达式构造，由深度机制递归消费，因此在槽位内使用记录字面量是合法的（`@set` 行同理）。

示例：

```promptscript
用户等级：{user.relationship_level.value ?? "未知"}
天气：{env.weather | 未知}
尊称：{user.vip == "svip" ? "，尊贵的" : ""}
标签：{vip_label[user.vip] ?? "未知"}
```

### 2.5 注释（C 风格）

采用 C 风格注释：`//` 行注释与 `/* */` 块注释，解析期剥离，不进入渲染产物；文章原文行中间位置的 `//`、`/*` 永不识别为注释。

## 3. 作用域与解析

### 3.1 解析与运行两阶段

```text
【解析期】读取 → 语法检查（未知名字一律不报错）→ 构建静态作用域表（hoist 所有 @set）+ include 展开
         → 存 AST。此阶段不做任何内容执行。
【渲染期】宿主提供绑定值 → 注入 → 求值 → 渲染。
```

- 语法错误在解析阶段失败。
- 语义错误（名字未绑定但实际被使用）在渲染阶段快速失败，并统一携带 `file:line` 定位信息。

### 3.2 作用域

- **帧**：一份文档的顶层作用域，绑定表结构为 `{ parent?, bindings }`。
- **作用域链**：当前帧 → 祖先帧（沿 include 链向上）→ 根帧的注入表。
- **include 创建子帧**：
  - 子帧可访问父帧的所有绑定。
  - 重名时以子帧为准（静默遮蔽）。
  - 子帧在 include 语句执行到该行时才求值（按需触发）。
  - 同一文件被 include 两次会形成两个独立子帧，彼此不可见。
- **统一名字空间**：字段、`@set` 和宿主注入共享同一个标识符空间，不存在“裸名 vs 点路径”的形状区分。
- `@set` 仅允许出现在帧顶层（即文章模式顶层），出现在块内导致语法错误。

### 3.3 静态规则（解析期）

| 规则                                 | 违规结果                                                           |
| ---------------------------------- | -------------------------------------------------------------- |
| `@set` 仅限顶层                        | 解析错误                                                           |
| 同帧 `@set` 重名                       | 解析错误（常量语义）                                                     |
| TDZ：`@set` 引用本帧其后声明的名字             | 解析错误（仅约束同帧声明之间；宿主注入永远“在前”，可自由引用）                               |
| `@set` 与宿主注入名同名（根帧）                | 渲染期错误（重复声明）                                                    |
| `@set` 与 include 子帧同名              | 子帧遮蔽，静默（正常遮蔽语义）                                                |
| `@for` 循环变量（块级）                    | 无（静默遮蔽外层同名绑定；不进帧级声明表）                                          |

解释：

- **提升**：所有 `@set` 声明被提升到帧顶部，但求值顺序仍按源码顺序。
- **TDZ（暂时性死区）**：`@set` 表达式不能引用同帧中后声明的 `@set`，防止循环依赖和顺序依赖；可以引用宿主注入和父帧的绑定。

### 3.4 词法

- **宽松标识符**：由不包含算子字符、空白和点（`.`）的连续文本组成，支持中文名。
  算子字符集：``{ } ( ) [ ] , : ? | & ! = < > " ' ` 空白``
  点（`.`）作为路径分隔符，不属于标识符的一部分。
- **字符串转义最小集**：`\"`、`\\`、`\n`、`\t`、`\{`、`\}`。其中 `\n` 在渲染期插入换行，不影响行结构解析。
- **中文引号**（`“”`）作为普通文本处理，不作为字符串定界符。
- **行尾空白**会被修剪；**行首空白**在文章模式下是内容的一部分，在代码模式下仅用于排版。
- **插值前后**不额外保留空白。

## 4. 运行时渲染

### 4.1 空缺判定矩阵

核心语义：**“解析为 `undefined`”（软空缺）与“从未解析”（硬空缺）是两种不同状态**。前者用于宿主功能未启用时的优雅降级，例如 `env.weather` 在天气功能未启用时为 `undefined`，模板渲染为空串或使用回退；后者通常意味着拼写错误或字段迁移后的残留引用，必须明确失败。

| 场景                                                                  | 结果                                                                     |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 根标识符未绑定 + 槽位实际渲染 + 无回退                                | 硬空缺，运行时错误                                                       |
| 同上 + 有回退（`??` / `\|` 任一）                                     | 回退                                                                     |
| 同上 + 位于假分支 / 已判空分支                                        | 无影响                                                                   |
| 绑定但值为 `undefined` / `null`                                       | 软空缺：有回退走回退，无回退渲染空串，不报错                             |
| 路径中间值为 `undefined` / `null`                                     | 整个路径解析为 `undefined`（软空缺），不继续访问属性                     |
| 路径访问到不存在的键（非自有键，且路径中间值不为 `undefined`/`null`） | 硬空缺（E_UNBOUND）                                                      |
| 记录键不存在（非自有键）                                              | 硬空缺（E_UNBOUND）                                                      |
| 记录键存在但值为 `undefined`                                          | 软空缺                                                                   |
| 绑定值直接渲染                                                        | string / number / boolean → 文本；null → 空串；记录 → 错误（必须取字段） |
| `@set` 表达式引用未绑定名                                             | 运行期错误                                                               |
| 谓词（`@if` / 三元条件）引用未绑定名                                  | 运行期错误                                                               |

路径解析规则细化：

- 解析路径时，若根标识符未绑定，则硬空缺。
- 若绑定值不是记录但仍有路径后缀（如 `user.name` 中 `user` 为字符串），则视为硬空缺（类型错误）。
- 若中间属性值为 `undefined` 或 `null`，则整个路径解析为 `undefined`（软空缺），不再继续访问属性。
- 若中间属性存在但为记录，继续解析下一段；若某键不存在（非自有键），硬空缺。

### 4.2 求值次序

1. **注入**：宿主提供的值合并为注入表，并前置到根帧。若与根帧的 `@set` 同名，则产生渲染期错误。
2. **帧求值**（按需触发，自上而下）：进入某个文档帧后，按源码顺序求值所有 `@set`，完成绑定。
3. **渲染**：深度遍历 AST，逐层求值 `@if`/`@else` 真值栈；`@for` 在节点处创建每次迭代的子帧并递归渲染循环体；include 子帧在对应语句处求值。
4. **槽位空缺判定**：按 4.1 的规则处理，并返回渲染结果。

### 4.3 错误分层

| 阶段     | 错误                                                                                         |
| ------ | ------------------------------------------------------------------------------------------ |
| 解析期    | 语法错误、`@set` 非顶层、同帧重名、TDZ 顺序错误、`@for` 格式错误（E_FOR_FORMAT / E_FOR_EXPECT_BRACE / E_FOR_RANGE） |
| 加载期    | include 文件缺失、include 循环引用                                                                  |
| 渲染期    | 注入名冲突、`@set` 引用未绑定名、槽位硬空缺、直接渲染记录、`@for` 迭代超上限（E_FOR_LIMIT）                                 |

所有错误都是携带 `file:line` 的可定位异常，消息直接面向作者；错误行为本身即契约。

## 5. 边界与转义

1. **字面花括号**：正文中的未闭合 `{` 或孤立 `}` 会导致解析错误（不会静默当作文本渲染）；如需输出字面花括号，应使用 `\{` 和 `\}`。在字符串字面量内，字面 `{` 使用 `\{`，字面 `}` 无需转义。
2. **花括号块**：`@if(expr) {` 单独占一行开启，`}` 独占一行闭合，或与紧随的 `@else` 同行连接，`@else {` 附着在紧邻的前一个完整 `@if` 块之后；配对按纯计数规则检查；未闭合或多余的 `}`、孤立的 `@else`、同一 `@if` 块出现多个 `@else` 均视为语法错误。
3. **空行语义**：块内空行表示纯空白，不渲染；如需输出空行，应写 `""` 字面量行。顶层空行则输出空行，用于段落分隔。
4. **槽位解析**：使用括号深度读取器，深度归零的 `}` 闭合槽位（引号内除外）；记录字面量由深度机制递归消费；槽位内需要输出字面 `}` 时使用 `\}`（引号内除外）。
5. **转义最小集**：`\"`、`\\`、`\n`、`\t`、`\{`、`\}`。
6. **记录键**：支持引号字符串、裸标识符和裸数字，统一字符串化；数字键仅允许下标访问。
7. **结构优先**：结构解析先于渲染，渲染产物永远不会回流到语法层（即使渲染出 `@if` 字样，也只是普通文本）。
8. **include 缩进**：子文件整体 dedent（以最小公共缩进为准，空行不参与计算）后内联；指令行按 `trimStart` 识别，与缩进无关。
9. **注释**：支持 C 风格 `//` 行注释与 `/* */` 块注释；解析期剥离，不进入渲染产物（见 2.5）。
10. **`??` 链**：左结合，没有数量限制。
11. **值内 `\n`**：在渲染期插入，不改变行结构。
12. **行尾空白**：会被修剪；行首空白在文章模式下是内容，在代码模式下仅用于排版。
13. **`@for` 块**：`@for` 行必须以 `{` 结尾、`}` 独占一行闭合，或与紧随的 `@else` 同行连接；`@else` 附着规则与 `@if` 相同；空迭代走 `@else`。
14. **`@for` 迭代上限**：32768 次（按单个 `@for` 计），超限渲染期报 `E_FOR_LIMIT`。
15. **`@for` 范围**：非负整数闭区间；`start > end` 为空迭代；范围语法仅 `@for` 局部可用。
16. **循环变量**：子帧绑定，静默遮蔽外层；循环外恢复；不进帧级声明表。
17. **include 读取缓存**：同一加载过程中同一路径只读一次磁盘。

## 6. API

```ts
// ─── 加载（include 需要文件系统；loadFile 可注入 → 浏览器 / custom loader 可用）
const ps = await PromptScript.load(path, { loadFile });
const ps2 = new PromptScript(text, { loadFile }); // 内存文本；@include 无 loadFile → 抛出清晰错误
await ps2.resolve(); // include 解析（幂等；load() 已内置，内存实例需显式）

// ─── 两阶段（宿主懒解析模式）
const missing = ps.collectMissing(); // string[]：scope 链解析不了的全部根标识符（去重、保序）
const values = await resolveFields(ctx, missing); // 宿主自己的惰性解析（包不负责这一点）
const text = ps.render(values); // 纯同步；同一实例可反复 render

// ─── 一次直渲（调试 / CLI / 测试；调用方已持有值，跳过 collectMissing）
const text2 = await PromptScript.render(text, values, { loadFile }); // static async

type Primitive = string | number | boolean | null | undefined;
type PromptValues = Record<string, PSValue>;
type PSValue = Primitive | Record<string, Primitive>;
type LoadFile = (path: string) => Promise<string> | string;
```

要点：

- `render(values)` 是纯同步函数，不执行 IO、无副作用；相同输入始终产生相同输出，因此可安全地用于快照、缓存或 LSP 场景。
- `resolve()` 具有幂等性：重复调用是安全的，已解析的实例会直接返回。`PromptScript.load` 内部已自动解析；通过内存文本构造的实例需要显式调用 `await ps.resolve()`。
- 本包不依赖宿主的字段体系：字段的含义与惰性解析方式完全由宿主通过 `values` 决定（BYO-fields）。
- 解析一次，可渲染多次。
- `collectMissing()` 返回路径的标识符，去重且保持出现顺序。它不返回由于中间属性为 `undefined` 而导致的软空缺路径，仅返回标识符未绑定的硬空缺引用。

## 7. CLI

```text
promptscript check <file…| ->   语法/静态作用域检查，逐条输出 file:line，exit 0/1（纯诊断，不渲染）
promptscript render <file|- > [values.json] [-v key=value …]   # "-" 表示 stdin；values JSON 为扁平 name→值映射
promptscript --version | --help
```

- `check` 仅执行解析期和加载期检查（包括 include 循环检测），不渲染，不产生语义错误（如未绑定名），但会检查静态可确定的错误（如 TDZ 顺序错误）。
- `render` 中 `values.json` 为扁平 name→值映射；`-v key=value` 可多次使用，优先于 JSON 文件（后出现的覆盖）。值默认为字符串，如需 number/boolean/null 应在 JSON 中提供类型。
- `-` 表示从标准输入读取文件内容。
